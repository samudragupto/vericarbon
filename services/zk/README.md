# VeriCarbon ZK Workspace (`services/zk`)

Zero-knowledge verifiable inference pipeline powered by **`ezkl==23.0.5`** (Halo2 / KZG over BN254).

## Workspace Artifacts (`services/zk/artifacts/`)

| File | Purpose |
| :--- | :--- |
| `circuit.onnx` | Compiled ONNX circuit combining feature commitment, tree ensemble evaluation, and the `claimedAmount <= model(quantizedFeatures)` inequality check. |
| `settings.json` | `ezkl` circuit configuration (`input_scale = 7`, `param_scale = 7`, `logrows = 13`, `input_visibility = "private"`, `param_visibility = "fixed"`, `output_visibility = "public"`). |
| `input.json` | Private witness input payload derived from `services/mrv/tests/fixtures/evidence_bundle.json` using the quantization scale parameters in `dataset_manifest.json`. |
| `compiled.ezkl` | Compiled Halo2 circuit binary produced by `ezkl.compile_circuit`. |
| `srs.params` | Local KZG Structured Reference String (`logrows = 13`) generated via `ezkl.gen_srs`. |
| `vk.key` / `pk.key` | Halo2 verification and proving keys generated by `ezkl.setup`. |
| `witness.json` | Computed circuit witness (`ezkl.gen_witness`). |
| `proof.json` | Generated Halo2 proof and 3 public instances (`[modelHash, dataCommitment, claimedAmount]`). |
| `workspace_meta.json` | Metadata manifest including Poseidon commitment over the input features, setup timing, and scale factors. |

## Statement Proved & Commitment Design

- **Private Input (`input_visibility = "private"`):** `quantizedFeatures` (`[1, 12]`, scaled consistently with `dataset_manifest.json`) + `claimedAmount` witness (`[1, 1]`).
- **Public Instances (`output_visibility = "public"`, `uint256[3]`):**
  1. `instances[0]` (`modelHash`): Fixed circuit constant derived from the SHA-256 digest of `services/mrv/tests/fixtures/model.onnx`, baked into `vk.key` (`param_visibility = "fixed"`).
  2. `instances[1]` (`dataCommitment`): In-circuit arithmetic feature commitment bound via `ezkl.poseidon_hash` feature commitment in `workspace_meta.json` (documented deviation: full 64-round bitwise SHA-256 inside an arithmetic Halo2 circuit requires >50,000 lookup rows, so ezkl Poseidon commitment is used in-circuit while the full SHA-256 `dataCommitment` is bound in the evidence bundle and registry as an off-chain audit pointer).
  3. `instances[2]` (`claimedAmount`): Evaluated via `Where(LessOrEqual(claimedAmount, model(quantizedFeatures)), claimedAmount, -1.0)`. When `claimedAmount <= model(quantizedFeatures)`, `instances[2]` equals `claimedAmount`; if `claimedAmount` exceeds the model prediction or is tampered with in calldata, `Halo2Verifier.verifyProof` reverts on-chain.
- **Laptop CPU Sizing Note:** To keep proving under `< 1s` on a single laptop CPU (`0.56s` proving time) and keep `Halo2Verifier.sol` under the 24KB EVM Spurious Dragon bytecode limit (`18,007` bytes deployed), the default circuit uses `num_trees = 4`, `tree_depth = 2` (`logrows = 13`). Full sweeps across `features ∈ {8, 16, 32}` and tree sizes are benchmarked in `eval/zk_benchmarks.py`.

## CLI Usage

```bash
cd services/zk
uv run zk setup
uv run zk prove --bundle ../mrv/tests/fixtures/evidence_bundle.json --out artifacts/proof.json
uv run zk verify --proof artifacts/proof.json
uv run pytest -v
```
